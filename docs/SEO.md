# SEO

## 1. Metadata

Defined in `src/app/layout.tsx` (defaults) and per-route `metadata` exports.

- Title template: `%s — ZWEAQ`, with a full default on the homepage.
- Every route sets its own `description` and an **absolute** `canonical`.
- Open Graph and Twitter cards on every route via the layout defaults.
- `metadataBase` is set, but asset URLs are built with `siteConfig.absolute()`
  rather than resolved against it — see §3.

## 2. Open Graph image

`/og.png`, 1200×630, generated by `npm run gen:renders`.

**PNG, not SVG, on purpose.** Several major consumers — Slack among them — do
not render SVG Open Graph images and show a blank card instead.

The image carries the "CONCEPT RENDER" label, so the honesty policy survives
into link previews where most people first see the product.

## 3. The base-path trap

This deployment lives at `https://kubegraf.github.io/zweaq.com`, under a path
prefix. That breaks the two idioms people reach for first:

```ts
new URL('/og.png', 'https://kubegraf.github.io/zweaq.com')
// → https://kubegraf.github.io/og.png     ← prefix silently dropped

icons: { icon: '/brand/favicon.svg' }
// → 404, because metadata icons do not get basePath applied
```

Both were real 404s during development, caught by watching the network panel
rather than by looking at the page. The fixes:

- `siteConfig.asset(path)` → `/zweaq.com/...` for same-origin references.
- `siteConfig.absolute(path)` → fully-qualified, prefix intact, for anything an
  external service will fetch.

A unit test asserts every schema URL still starts with the site URL.

## 4. Structured data

| Schema | Where |
|---|---|
| `Organization` | Every page, from the layout |
| `Product` | Homepage and `/product` |
| `FAQPage` | Homepage |
| `BreadcrumbList` | Every sub-page |

**The `Product` schema publishes no `offers` block.** There is no price, no
availability, and no way to buy. Emitting an offer would tell search engines the
product can be bought — which is false, and would earn a rich-result penalty
alongside being dishonest. A unit test asserts `offers`, `InStock` and
`PreOrder` never appear.

`additionalProperty` carries the same `Target:` qualifier the page shows, so the
honesty policy holds in structured data too.

`sameAs` is omitted entirely rather than emitted empty, because no social
profiles are configured.

## 5. Crawling

- `src/app/robots.ts` — allows everything, points at the sitemap.
- `src/app/sitemap.ts` — all nine public routes with absolute URLs.
- `priority` is deliberately omitted; Google has said for years that it ignores
  it.

## 6. Semantics

- One `h1` per page, heading levels never skip — asserted in E2E.
- `<nav>`, `<main>`, `<footer>`, `<section aria-labelledby>` throughout.
- Tables use `<caption>`, `<th scope>` — the comparison and gesture tables are
  real tables, not divs.
- FAQ answers live in `<details>`, so they are in the HTML while collapsed and
  are crawlable and findable with browser find-in-page.
- Every route is statically prerendered; there is no client-only content.

## 7. Performance signals

- No layout shift from fonts: self-hosted, `display: swap`, tuned fallbacks.
- No third-party requests at all — nothing to block LCP.
- The hero is inline SVG, so the largest contentful paint needs no image fetch.
